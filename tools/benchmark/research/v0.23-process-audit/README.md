# Research process audit before resuming engine experiments

The user reports hitting the five-hour limit while using 16% of the weekly
allowance without reaching a promotion recommendation. No per-action token
meter is available here; a numerical savings claim cannot be measured from
these files. The audit targets avoidable model work rather than weakening
correctness, equal-time controls, raw retention or the standard game screen.

| Observed process cost | Replacement | Preserved boundary |
| --- | --- | --- |
| Near-duplicate native, warm and fresh drivers per hypothesis | Shared plan builders, runner and parameterized generator | Same budgets, trials, worker counts, seeds/exclusions and gates |
| Repeated short polling plus separate file reads | Stage progress and compact workflow status, bounded waits | Failures/interruption remain visible and logs remain complete |
| Manual arithmetic and large quality JSON/PV dumps | Warm report and choice brief with worst adverse IDs | Full records retained; targeted diagnosis still uses raw evidence |
| Handwritten snapshots, module-format repair and inventories | Source snapshot/replay module support and inventory commands | Base/source/input/output identities checked; no overwrite |
| Reconstructing context from many experiment files | Compact checkpoint and one tooling map/flowchart | Reassessment still includes earlier research and adverse evidence |
| Completing more timing pairs after a deterministic node gate has already failed | Prospectively declared early node gate | Failed criterion is not weakened or relabeled |

The [tooling guide](../../../../docs/RESEARCH_TOOLING.md) describes the complete
flow, exact command roles and repeatable examples. The root agent guidance and
standard research workflow link it. Historical driver programs remain evidence,
not recommended scaffolding for new attempts. No general distributed framework,
model-driven watcher, automatic tuning or publication loop is introduced.

The runner is deliberately small and sequential between explicit stages. Darwin/
Linux use a repository measurement lock and process-group cancellation; internal
three-worker native queries and the standard concurrent match remain unchanged.
Input/plan changes, output tampering, missing reports, failed gates and incomplete
steps fail closed. Resume does not rerun or bypass failure. Only passed steps
are reusable, and reference caches retain their existing matching checks.

The first tooling tests catch a real resume bug: unmarshalling saved identities
into a map shared with freshly hashed inputs overwrites the comparison operand.
Load saved state separately before comparison. The initial failed output stays
in `initial-tooling-tests.txt`; regression coverage checks changed inputs,
plans and outputs, gate rejection, command errors and timeout behavior.

No engine hypothesis is selected by this tooling. The current capture-futility
diagnosis was already collected when the audit was requested; its decision and
any next implementation wait until the tooling audit is complete. Earlier six
failures and their one 150-game screen remain preserved. After validation,
resume local research and check in before committing a recommended candidate.

Validation is complete: the full normal/race suites, focused plan regressions,
vet, native build and Linux/amd64 tool build pass. The shared runner recomputes
the preserved child-reuse rejection (0.908627 median ratio), verified-pass
rejection (1.001103 and 0.901113 node ratio) and compact-pawn cost pass (1.039501)
without running engines again. Expected historical failures remain false; the
audit run passes because it preserves those decisions. All legal/depth/identity
checks have zero issues. A source snapshot including the declared nested module
files also replays, tests and builds without a repaired overlay. See
`tooling-plan.json`, `tooling-run/state.json` and the preserved logs/reports.

Remaining limits: no measured token-savings percentage, no automatic scientific
judgment, and no protection against unrelated system load or manually launched
legacy jobs. OS measurement locking coordinates shared runner jobs, not every
process on the computer. Existing frozen research gates are unchanged. The new
optional root harness performs no work without explicit workload/output inputs.
