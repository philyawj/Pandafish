# Reassessment after the contextual-evaluation rejection

The defender-aware evaluator improves old public decisions but fails the newer
100ms mean-loss gate for both turns, with roughly 28% fewer searched nodes.
Archive it without games and restore v0.22. No coefficients, thresholds or cache
rules are changed to rescue it. The unconsumed fresh-control design remains
available; its results have not been queried.

The live campaign is one diagnostic source, not an overriding priority list.
Revisit the threads that preceded it: low-cost checking generation/tactical
reach, remaining exact backend work and a genuinely different contextual model.
The old child-storage, aspiration/history, clock and reuse attempts keep their
failed outcomes. Later kernel changes can alter opportunity but do not turn
those failures into passed tests.

Before selecting between checking search and another exact backend project,
profile restored v0.22 on the prior frozen 20-game warm workload at depth five.
This retains the same 1,145 roots and all ten openings, persistent per-game
tables and real iterative entry point. The source helper is unchanged from
the earlier study; profiling includes setup, MemStats and output overhead.
Use it to rank opportunities, not to claim an elapsed saving. No candidate
implementation or extra old-code screen follows merely from allocation bytes.

The next selection should favor a substantive mechanism with measured room:
new checking-only generation and bounded quiescence checks if missing tactical
reach dominates; a new exact state/generation optimization only if the current
profile supports larger elapsed headroom. A differently scoped reuse of archived
code needs a prospective plan and preserves the original failure explicitly.
